# V11 — 실제 자료 화면 5장과 주식 원고 품질 개선 설계

2026-10-12, Asia/Seoul. 상태: 2026-10-12 사용자 승인 완료. 제품 코드 변경·실제 초안 저장 완료를 뜻하지 않는다.

## 사용자 요구와 성공 기준

사용자는 V10을 기반으로 V11을 개발하고 있다. 우선순위는 제목·본문·이미지의 완성도이며, 회사 홈페이지의 회사 소개 화면과 네이버페이 증권의 특정 화면을 캡처해 첨부하려고 한다. 기존 5장 모두 실제 회사·주식 자료 화면 캡처로 구성한다는 답변을 받았다.

새 작업은 아래 역할의 실제 캡처 5장, 근거와 연결된 원고, 네이버 입력용 이벤트를 준비한다. 공개 발행은 사용자가 한다. 기존 작업의 승인·입력·저장 기록은 기존 계약으로 재개하며 새 이미지 계약을 소급 적용하지 않는다.

## 5장 배치

| 순서 | 역할 | 기본 출처·화면 | 원고에서 다루는 내용 |
|---|---|---|---|
| 1 | company_intro | 공식 홈페이지 회사 소개의 대표 영역 | 어떤 회사인지와 핵심 특징 |
| 2 | market_overview | 네이버페이 증권 기업현황 또는 종목 요약 | 상장시장·기업 규모 |
| 3 | price_history | 네이버페이 증권 차트·시세의 선택한 기간 차트 또는 52주 가격 요약 | 표시 기간의 가격 움직임과 마지막 가격 |
| 4 | business_structure | 공식 사이트 사업분야·제품 소개, 또는 네이버페이 주요제품 매출구성 | 무엇을 만들거나 판매하는지 |
| 5 | performance_context | 공식 IR 실적 화면 또는 네이버페이 재무분석의 실제 실적 영역 | 다음 자료에서 점검할 사업·실적 관련 항목 |

각 역할의 URL과 캡처 영역은 해당 종목의 실제 UI를 확인해서 기록한다. 정보가 겹치는 동일 화면을 두 장으로 중복 사용하지 않는다. 다섯 역할에 맞는 화면이 부족하면 필요한 역할과 확인할 출처를 알려준다. 목표주가·매수추천을 담은 컨센서스 화면은 기본 출처로 선택하지 않는다.

5번은 현재 원고의 체크포인트를 보조하는 자료 화면이다. 새로운 매출·이익·증감률을 본문에서 주장하려면 승인된 사실 계약과 근거가 있어야 한다. 이번 변경에서 캡처의 숫자를 근거 필드 없이 자동으로 원고에 추가하지 않는다.

## 수집 방식의 선택

권장 방식은 **네이버페이 공통 캡처 프로필 + 회사 사이트별 확인한 영역 설정**이다. 네이버페이의 종목 식별·탭·프레임·기간 선택은 공통화하고, 회사 사이트는 실제로 확인한 URL·영역·식별 문구를 작업별 설정에 기록한다. V10의 캡처 준비 검사와 PNG 저장 흐름을 재사용한다.

대안은 작업마다 모든 URL·영역을 수동 지정하는 방식이다. 처음 연결하기는 단순하지만 같은 UI 검증을 매번 반복해야 한다. 회사별 고정 수집기를 전부 만드는 방식은 사이트 수가 늘수록 유지 비용이 커지므로 첫 구현에서는 채택하지 않는다.

## 확인한 실제 화면

삼성전기를 예시로 공개 UI를 확인했다.

- [삼성전기 소개](https://www.samsungsem.com/kr/about-us/company/overview.do): 회사 소개 대표 화면과 컴포넌트·모듈·기판 사업분야가 있다.
- [네이버페이 기업현황](https://stock.naver.com/domestic/stock/009150/info/company): 종목명·코드, 시세·기업 규모 자료가 있다.
- [차트·시세](https://stock.naver.com/domestic/stock/009150/price): 1년 기간 선택과 52주 가격 요약이 있다. 1년 차트의 눈에 보이는 최고·최저를 52주 원천 값으로 대신하지 않는다.
- [기업개요](https://stock.naver.com/domestic/stock/009150/info/overview): 주요제품 매출구성 영역이 있다.
- [재무분석](https://stock.naver.com/domestic/stock/009150/info/financial): 연간·분기 선택, 재무 그래프와 표가 있다.

기업현황·재무분석은 `navercomp.wisereport.co.kr`의 FnGuide 프레임을 포함한다. 부모 페이지와 실제 프레임의 URL·호스트를 모두 기록한다. 프레임의 DOM이 읽혀도 부모 화면에 로딩 표시가 남는 사례가 관찰됐다. DOM 존재만으로 캡처 준비 완료를 판정하지 않는다.

현재 가격·52주 범위에는 KRX+NXT 통합 기준, 시가총액·투자지표에는 KRX 기준 안내가 있었다. 시장·기간·가격 조정 기준을 원문 그대로 기록하고 수치를 같은 기준으로 간주하지 않는다.

네이버페이와 FnGuide 화면에 무단 재배포·사용 제한 안내가 있다. 운영 자료에 사용 허용 근거를 기록해야 하며, 예시 캡처는 사용권이 승인된 게시용 자산으로 표시하지 않는다.

## 이미지 계약과 기존 작업 호환

새 `job:init` 작업에는 `conditions.imageLayout=stock_sources_five_v1`을 명시한다. 이 값이 없는 기존 작업은 현재 카드·AI 이미지 계약으로 처리한다.

새 모드의 역할은 위 5개이고 `assetKind=source_screenshot`을 사용한다. 실제 PNG의 크기와 비율을 보존하며 1200×1200 조건을 적용하지 않는다. 역할별 출처·자료 기준일·캡처 시각·캡처 영역·종목 식별 결과·SHA-256·크기·검토 상태를 저장한다. 별도 프레임이면 부모 URL과 프레임 URL을 함께 둔다.

새 모드에서 카드 렌더링과 AI 콘셉트 이미지 준비를 필수 단계로 요구하지 않는다. 기존 모드의 렌더러와 승인·재개 검증은 유지한다. 이미 입력한 작업의 구성을 바꾸려면 새 작업을 만든다.

## 캡처 단계와 사실 검증

`capture:run`은 검토한 화면 설정과 종목 식별 근거로 이미지를 준비한다. 금융 제공자 파일이 아직 없으면 캡처 준비와 금융 검증 상태를 구분한다. 캡처 성공을 금융 사실 검증 성공으로 보고하지 않는다.

단계별로 다음을 검사한다.

1. 회사명·종목코드·시장·공식 도메인과 허용된 자료 호스트를 확인한다.
2. 화면의 탭·선택 기간·표의 연도·실제치/예상치·단위와 데이터 기준을 기록한다.
3. 필요한 프레임과 이미지가 로딩되고 광고·팝업·고정 패널이 중요 정보를 가리지 않는지 확인한다.
4. 영역을 실제로 캡처하고 원본 비율·크기·해시·출처를 저장한다.
5. 다섯 장을 시각 검토한 뒤 현재 이미지 집합의 fingerprint로 승인한다.
6. 원고에서 사용하는 숫자·기업 사실은 별도의 승인된 사실과 연결해 검수한다.

권한·출처·기준이 없거나 화면이 가려지고 잘렸거나 선택 대상이 모호하면 `needs_user`로 중단한다. 데이터 변경 시 기존 이미지·원고 승인은 무효화한다.

## 제목과 본문 개선

제목은 기업 특징과 실제 독자 질문을 중심으로 7개 후보를 만든다. 사업·기업 규모·가격 읽기·초보자 상황 등 관점을 달리하고, 본문이 실제로 답하는 후보를 선정한다. 첫 후보를 자동 선정하는 고정 규칙을 제거한다.

본문은 기존 5개 섹션의 역할을 유지한다. 도입에서 기업의 구체적인 특징을 먼저 제시하고, 각 절에 새 정보를 담는다. 공통 확인 문장을 반복해 분량을 채우지 않는다. 이미지 파일 경로·검수 과정·제목 후보는 공개 본문에 넣지 않는다. 제목·본문을 먼저 구성하고 해당 절에 실제 자료 이미지를 배치한다.

새 작업의 기본 분량은 현재 V11 기준인 본문·소제목·캡션·출처 합계 800–1000자로 유지한다. 사용자 지정이 우선한다. 캡션은 회사·화면 주제·출처·자료 기준을 짧게 기록하고 SmartEditor 사진 설명칸에 넣는다.

근거 없는 숫자·한글 금액·기업 사실·권유 표현이 통과한 기존 점검 사례를 회귀 검증에 포함한다. 사실 주장과 교육 설명·점검 의견을 구분하고, 원고를 바꾸면 현재 원고에 대한 검토 기록도 갱신한다.

## 변경 대상과 검증

- 작업·자산 계약: 새 이미지 모드와 역할, 기존 작업 해석 유지.
- 수집·캡처: 공통 화면 설정, 네이버페이 탭·프레임·기간 처리, 역할별 캡처 영수증.
- 이미지 검사: 5장 순서·종목·출처·기간·비율·해시·승인 상태.
- 원고: 사실 기반 후보 생성·선정, 회사별 문장, 근거·캡션 연결.
- CLI·문서: 새 캡처 흐름과 기존 렌더 흐름 구분.
- 입력·저장: 새 자산 계약을 전달하면서 기존 소유 탭·입력 확인·불확실 저장 처리를 유지.

자동 검증은 `pnpm test`, `pnpm typecheck`, `pnpm build`다. 서로 다른 캡처 비율, 4장/6장/순서 오류, 종목 혼동, 프레임 호스트 변경, 로딩·가림, 원고 검증 빈틈, 기존 작업 재개를 검사한다.

실제 검증은 사용 허용 근거가 준비된 한 종목에서 5장 모두를 원본 화면과 대조하고, 원고·사진 설명·네이버 임시저장 재열람까지 별도로 기록한다. 모의 테스트를 실제 계정 검증으로 보고하지 않는다.
